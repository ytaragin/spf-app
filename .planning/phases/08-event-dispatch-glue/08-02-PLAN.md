## Phase Goal

**As a** player joining or watching a live game, **I want to** see the game start and both teams'
lineups appear on my board as the server announces them, **so that** my view matches the opponent's
without polling.

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-08-07 | Tampering | `dispatchEvent` GameStarted branch | high | mitigate | `data` is validated as a non-null object before any store call, and the state is then gated by `applyGameState` — a forged stale `GameStarted` cannot regress `gameState` (D-08, D-15). |
| T-08-08 | Tampering | `applyLineup` | medium | mitigate | `lineups.value[side]` is a whole-reference assignment with `side` restricted to the two literals `'offense'` / `'defense'` chosen inside `dispatchEvent` — never taken from the payload — so no attacker-controlled key (including `__proto__`) can be written. Asserted by the absence of a payload-derived index in the source. |
| T-08-09 | Tampering | `dispatchEvent` lineup branches | high | mitigate | Non-object `data` is rejected with zero store calls; a wrong backend shape degrades to "ignored + loud log", never to corrupt state (D-08, D-11). |
| T-08-10 | Information disclosure | `console.error` in new branches | medium | mitigate | Messages interpolate only the event tag; asserted by the `.not.toContain('top-secret-value')` tests. |
| T-08-11 | Elevation of privilege | dispatch → `setLineup` | high | mitigate | The lineup branches call `applyLineup` (local-only) and never `setLineup` (POSTs to `/offense/lineup`). Asserted by `grep -c 'store\.set'` returning 0 (D-05, D-06). |
| T-08-12 | Repudiation | ignored events | low | accept | Client-side SPA with no audit requirement; the `console.error` breadcrumb is sufficient diagnostics for Phase 9/11. |
